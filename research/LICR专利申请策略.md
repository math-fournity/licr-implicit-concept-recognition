# LICR专利申请策略指南

## 执行摘要

LICR（LLM-based Implicit Concept Recognition）技术属于**"基于AI算法的功能或领域应用"**类专利，在中国和美国均有明确的申请路径。关键是将技术方案与具体应用场景绑定，避免被认定为"智力活动的规则和方法"。

---

## 第一部分：专利性分析

### 1.1 LICR的技术创新点

| 创新点 | 现有技术 | LICR创新 |
|--------|---------|----------|
| 识别目标 | 显式实体（文本中出现的） | **隐性概念**（文本体现但未命名的） |
| 识别机制 | 表面形式匹配 | **语义模式推断** |
| 架构设计 | 端到端实体链接 | **LLM+API混合架构**（语义理解+精确映射分离） |
| 知识库链接 | 字符串匹配 | **概念名称→API查询** |

### 1.2 可专利性要件分析

#### 中国专利法视角

| 要件 | 分析 | 结论 |
|------|------|------|
| **客体适格性** | LICR不仅是算法，还涉及文本处理、知识库查询、数据结构转换等技术特征 | ✓ 符合 |
| **新颖性** | 现有Entity Linking系统（FALCON、mGENRE）均只处理显式实体，LICR首次解决隐性概念识别问题 | ✓ 符合 |
| **创造性** | 提出"语义理解与标识符映射分离"的新架构，解决了LLM无法可靠记忆Q号的问题 | ✓ 符合 |
| **实用性** | 可直接应用于知识图谱构建、语义搜索、文档分类 | ✓ 符合 |

#### 美国专利法视角（35 U.S.C. § 101）

| Alice/Mayo测试 | 分析 | 结论 |
|----------------|------|------|
| **Step 2A Prong 1** | LICR涉及"从文本中推断概念"，可能被认为是抽象概念 | ⚠️ 需谨慎 |
| **Step 2A Prong 2** | 但LICR整合到具体技术应用中：知识图谱构建、API调用、数据库索引 | ✓ 实际应用 |

## 第二部分：权利要求撰写策略

### 2.1 核心原则（中美通用）

根据国家知识产权局2024年12月发布的《人工智能相关发明专利申请指引》和USPTO 2024年AI专利指南：

1. **不要只写算法**，必须与"技术特征"结合
2. **明确技术问题**：现有实体链接系统无法识别隐性概念
3. **明确技术效果**：扩展知识图谱覆盖范围、提高语义搜索召回率
4. **避免纯数学描述**：强调数据流、系统架构、API交互

### 2.2 推荐的权利要求结构

#### 独立权利要求1（方法权利要求）

```
一种基于大语言模型的隐性概念识别与知识图谱链接方法，包括以下步骤：

S1. 接收待处理的文本数据；

S2. 将所述文本数据输入至大语言模型，所述大语言模型根据预设的隐性概念
    识别提示词，从所述文本数据中推断出文本所体现但未显式命名的隐性概念，
    输出隐性概念名称列表；
    
    其中，所述隐性概念包括但不限于：方法论概念、领域原理、抽象模式；
    所述隐性概念识别提示词包含概念类型层次定义和证据提取要求；

S3. 针对所述隐性概念名称列表中的每个概念名称，调用知识库API进行查询，
    获取对应的知识库标识符；
    
    其中，所述知识库API为Wikidata实体搜索API或等效知识库API；

S4. 将所述文本数据、隐性概念名称和知识库标识符关联存储，构建隐性概念
    知识图谱索引。
```

#### 独立权利要求2（系统权利要求）

```
一种隐性概念识别与知识图谱链接系统，包括：

文本输入模块，配置为接收待处理的文本数据；

隐性概念识别模块，包含大语言模型和隐性概念识别提示词，配置为：
    - 分析所述文本数据的语义结构；
    - 推断文本所体现但未显式命名的隐性概念；
    - 输出隐性概念名称及其文本证据；

知识库映射模块，配置为：
    - 接收所述隐性概念名称；
    - 调用外部知识库API查询对应的知识库标识符；
    - 处理消歧和多候选排序；

知识图谱构建模块，配置为：
    - 建立文本块与隐性概念的EMBODIES关系；
    - 存储隐性概念节点及其知识库标识符属性；
    - 生成可查询的隐性概念索引。
```

#### 独立权利要求3（计算机可读介质）

```
一种计算机可读存储介质，存储有计算机程序，所述计算机程序被处理器执行时
实现权利要求1所述的方法。
```

## 第四部分：说明书核心内容

### 4.1 技术背景（建议内容）

```
【技术领域】
本发明涉及自然语言处理和知识图谱构建领域，特别涉及一种基于大语言模型
的隐性概念识别与知识图谱链接方法及系统。

【背景技术】
实体链接（Entity Linking）是将文本中的实体提及映射到知识库标识符的任务。
现有系统如FALCON 2.0、mGENRE、BLINK等均依赖表面形式匹配，只能识别
文本中显式出现的实体。

然而，文本常常"体现"某些概念而不显式命名它们。例如，一段数学证明文本
"假设√2 = p/q，p和q互质...导出矛盾...因此√2是无理数"完整展示了
"反证法"（proof by contradiction）的逻辑结构，但"反证法"一词从未出现。
现有实体链接系统无法识别这类隐性概念。

本发明人将此类问题定义为"隐性概念识别问题"（Implicit Concept Recognition 
Problem, ICRP），并发现现有技术对此完全无能为力。
```

### 4.2 发明内容（建议内容）

```
【发明内容】

针对现有技术的不足，本发明提供一种基于大语言模型的隐性概念识别与知识
图谱链接方法及系统。

本发明的核心洞察是：
1. 大语言模型具备识别文本中隐性概念的能力（语义理解层面）；
2. 大语言模型无法可靠输出知识库标识符（Q号是任意编码，非语义信息）；
3. 因此，最佳架构是将语义理解与标识符映射分离：
   LLM（语义理解）→ 概念名称 → 知识库API（精确映射）→ 标识符

本发明的技术效果包括：
1. 扩展知识图谱覆盖范围：从显式实体扩展到隐性概念；
2. 提高语义搜索召回率：可检索"使用反证法的文档"而非仅"提及反证法的文档"；
3. 实现跨文档概念关联：自动关联所有体现相同方法论的文档。
```

### 4.3 实验数据（建议内容）

```
【实施例】

本发明人设计了5个跨领域测试案例验证本发明的有效性：

测试1：数学证明（√2无理性证明）
  输入：反证法证明文本（不含"反证法"术语）
  输出：成功识别"proof by contradiction"并链接到Wikidata Q184899
  
测试2：算法描述（快速排序描述）
  输入：分治递归排序描述（不含"quicksort"术语）
  输出：成功识别"quicksort"、"divide and conquer"
  
[...更多测试案例...]

实验结果：
- 核心隐性概念召回率：100%
- 整体准确率：96%
- 知识库标识符准确率（通过API）：100%
```
